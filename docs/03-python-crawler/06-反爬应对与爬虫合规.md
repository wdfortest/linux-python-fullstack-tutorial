# 第 6 章 · 反爬应对与爬虫合规

> 本章配套代码：无（本章是判断与边界章，不提供针对真实站点的采集代码）
> 建议学习时长：约 3 小时

## 学习目标

学完本章，你能够：

1. 认全主流反爬手段（UA/频率/IP/验证码/JS 渲染/接口加密/登录态），并说明每类手段针对什么问题；
2. 用合法手段应对「被限流」：降速、退避、诚实标识，而不是对抗；
3. 快速判断一个页面是否 JS 渲染，并选对处理路线（找接口 / 渲染引擎 / 放弃）；
4. **说清为什么验证码「不该绕」**——技术之外的合规底线；
5. 概述数据采集相关的法律框架（网络安全法、数据安全法、个人信息保护法、刑法、反不正当竞争法）与高风险行为清单；
6. 用 10 条自查清单审查一个爬虫项目的合规性，知道在哪里寻求法律意见。

## 6.1 前置知识 / 本章地位

前五章你已掌握完整采集技术；本章回答两个前置技术解决不了的问题：**对方不让你抓怎么办**（反爬）与**你究竟有没有权利抓**（合规）。本章刻意不提供任何针对真实站点的对抗性代码——这不是能力问题，而是本仓库的内容红线：教程可以教的对抗手段（打码、指纹伪造、代理池对抗）恰好是司法实践中把开发者送进麻烦的行为模式。第 7 章的 Selenium 属于「正常浏览器能力」，与「对抗」有本质区别，届时会再划一次界。

本章没有 lab 的原因也在此：反爬对抗没有「安全靶场」可以替代真实站点（练习站根本不设反爬），而合规是判断力训练而非编码训练。本章的「动手」形式是 6.7 的清单审计与练习 1 的代码对照。

## 6.2 反爬手段全景

| 反爬手段 | 识别方式 | 对爬虫的影响 | 对应的「合法应对」 |
|---|---|---|---|
| User-Agent 检查 | 请求头不像浏览器/在黑名单 | 403 或返回假页面 | 用真实身份标识（本仓库规范：教育用途 UA + 联系方式） |
| 频率限制（限流） | 同 IP 请求过密返回 429/503 | 请求被拒 | **降速 + 退避**；尊重 429 是义务不是策略 |
| IP 封禁 | IP 段被拉黑 | 整段 IP 不可用 | 降低频率避免触发；被封说明已经太迟 |
| Cookie/登录态 | 内容仅登录可见 | 拿不到数据 | 只处理你**有权**访问的内容；共享账号/破解登录属违规 |
| 验证码 | 高频或可疑行为触发 | 请求被拦截 | 放慢到不触发的程度；**绝不打码绕过**（见 6.5） |
| JS 渲染 | 源码里没有数据 | requests 拿到空壳 | 找 XHR 接口（第 1 章）或浏览器渲染（第 7 章） |
| 接口参数加密/签名 | XHR 带 token/sign 且逻辑混淆 | 直接调接口失败 | **停止**：逆向加密属于对抗行为，法律风险陡增（见 6.6.2） |
| 行为分析/设备指纹 | 分析点击轨迹、TLS 指纹 | 正常请求也被识别 | 没有合法的「应对」——被识别通常说明访问模式异常，先自省频率与身份 |
| 蜜罐链接 | CSS 隐藏的「只给爬虫点」的链接 | 点了即被标记拉黑 | 只提取渲染后可见的链接（第 7 章渲染后过滤）；发现疑似蜜罐立即停手 |
| 页面级禁抓指令 | `<meta name="robots">` 或 `X-Robots-Tag` 响应头 | 与 robots.txt 互补的页面级意愿表达 | 与 robots.txt 同等对待：`noindex/nofollow` 的页面不采、不跟 |

这些手段普遍组合使用（UA 检查在最外层、限流在中层、验证码兜底），所以「降速降到位」往往一次性化解外中两层的多数拦截——这也是先自省频率、再考虑其他因素的工程依据。

读表的关键视角：反爬的本质是**服务器在表达「这样的访问我不欢迎」**。合法应对的共同点是「让访问模式回到服务器欢迎的范围」；对抗式应对的共同点是「让不合规的访问模式更难被识别」——后者正是越界的开始。

### 6.2.1 站点视角：限流是怎么实现的

理解对方怎么做限流，你的「降速」才有依据。常见算法的工程直觉：

- **滑动窗口计数**：以 IP（或账号、API key）为单位，统计「最近 N 秒内的请求数」，超过阈值即拒绝。你的爬虫触发它的方式通常是「并发短促地连发」；
- **令牌桶**：桶里以固定速率生成令牌，每个请求消耗一枚，桶空则拒绝——允许短时突发、但平均速率被卡死。你把请求间隔拉匀到令牌生成速率以下，就永远不会碰壁；
- **分级响应**：多数站点不是一步到位封禁，而是「高频 → 丢验证码 → 更高频 → 429/封 IP」。**验证码与 429 是逃生通道，不是对抗的起点**：看到它们立刻退避降速，通常不会被进一步处置。

这解释了 6.3 的三板斧为什么有效：你的请求模式退回到「一个有耐心的普通用户」的形态，限流器就没有理由针对你。

## 6.3 合法应对三板斧：降速、退避、诚实标识

被限流时的标准动作，全部已在前几章的代码里出现过：

1. **降速**：把请求间隔调大（0.3s → 1s → 3s），并发调小（第 5 章 AutoThrottle 的动态版思路）。多数限流在降速后自然解除；
2. **退避重试**：对 429/503 使用**指数退避**（1s → 2s → 4s → …），重试若干次仍失败则记录后跳过（第 2 章 2.4.2 的封装把 4xx 排除在重试外，正是这个原因——429 要的是「慢下来」，不是「再试一次」）；
3. **诚实标识**：UA 写清项目与联系方式，站点管理员发现问题能找到你，而不是直接封禁。这是被海量实践验证过的最低成本策略——**可联系的爬虫通常先收到警告，匿名的爬虫通常先收到封禁**。

一个工程判断：如果你的爬虫在规范限速下仍被拦截，正确动作是**停下来评估**（robots.txt、服务条款、数据性质），而不是加代理换 IP 继续压。后者的每一步都在积累法律与封禁风险。

指数退避的具体参数（第 2 章封装的配置版）：

| 重试次数 | 等待 | 触发条件 |
|---|---|---|
| 第 1 次 | 1s | 连接错误/5xx |
| 第 2 次 | 2s | 同上 |
| 第 3 次 | 4s | 同上，之后放弃并记录 |
| 收到 429 | ≥30s 或按 `Retry-After` 响应头 | **不按上表**，先降速再谈重试 |

HTTP 规范允许服务器在 429 响应里携带 `Retry-After` 头（秒数或日期）——它等价于对方明确告诉你「多久以后再来」，这是唯一应该**无条件服从**的重试参数。

频率参数的参考基线（全篇 lab 一致执行，供你配置新项目时对照）：

| 场景 | 建议请求间隔 | 建议并发上限 |
|---|---|---|
| 练习站（本教程主线） | ≥ 0.3s | ≤ 5 |
| 一般内容站 | 1–3s | 1–2 |
| robots.txt 声明 Crawl-delay 的站点 | ≥ 该值 | ≤ 2 |
| 官方 API | 按其文档的速率限制 | 按配额 |

另有「错峰」技巧：把每日任务的启动时刻放在访问低谷（如凌晨），既是礼貌也降低被运维注意的概率——注意这是「避开高峰」，不是「趁没人干坏事」，两者在技术上相似、在性质上相反。

## 6.4 JS 渲染：判断与正确路线

判断方法（第 1 章 1.5 节的方法在此复用）：

1. 「查看网页源代码」搜页面上的关键词——搜不到 → 数据由 JS 生成；
2. Network 面板筛 XHR——找一个返回 JSON 的数据接口，**找到就优先直接调它**（合规且高效，注意频率礼仪不变）；
3. 接口也找不到/接口参数复杂 → 上浏览器渲染（第 7 章 Selenium）。

三条路线的成本与合规排序：**XHR 接口 > 浏览器渲染 > 逆向参数**。浏览器渲染用的是普通用户能力（一个真浏览器在正常浏览），不涉及破解；逆向加密参数则进入对抗区。练习站的 `/js/` 页面是前两条路线的实验场（第 7 章 lab 已演示）。

用一个具体例子走一遍判断流程——假设目标是 `quotes.toscrape.com/js/`：

1. 「查看源代码」搜 `The world as we have created` → 搜不到，确认 JS 渲染；
2. Network 面板刷新观察 → 该页没有 XHR 数据接口（内容直接由内联 JS 生成）；
3. 结论：requests 路线出局，走第 7 章浏览器渲染——lab 实测 `page_source` 里能解析出 10 条名言。

对照 `quotes.toscrape.com/tag/love/`（普通页面）：源码里直接有数据 → 第 2 章 requests 路线即可。**同样的站点，不同页面走不同路线**——路线决策按页面做，不按站点做。

## 6.5 验证码为什么「不该绕」

技术上「打码」（OCR/机器学习识别图形验证码、接入打码平台）是存在的，但本仓库不提供且劝你不要做，理由三层：

1. **合规层面**：验证码是站点明确的「拒绝自动化访问」信号。绕过它 = 绕过访问控制，一旦发生纠纷，「明知有访问控制仍系统性地绕过」是认定主观故意最直接的证据（司法案例里反复出现这一要件）；
2. **法律层面**：绕过验证码常与《刑法》第 285 条的认定挂钩——「避开或突破安全保护措施」是非法获取计算机信息系统数据罪的构成要件之一，验证码、登录墙、加密参数都属于此类措施（具体认定以司法解释与裁判为准）；
3. **工程层面**：打码平台意味着把目标站点的验证码图像交给第三方处理，数据链路失控，很多平台本身游走在灰色地带。

遇到验证码的唯一推荐动作：**让程序停下来**，记录日志，降低频率或人工评估是否该继续这个采集任务。

如果你收到的是「帮公司绕过验证码采集 XX 数据」这类需求，回应模板可以参考三句话：说明技术行为属于绕过访问控制（第 6.6.2 条清单第 1 条）；指出对应刑法 285 条与不正当竞争风险（6.6.4 的责任层级）；给出替代方案（官方 API 授权 / 数据方商务合作 / 更换公开数据源）。多数「必须爬」的需求在第二句就失去了必要性。

## 6.6 合规与法律边界（重点）

> 本节是技术作者写给你的「工程师法律常识地图」，**不构成法律意见**；涉及真实商业决策，请咨询执业律师并核对法律现行文本。

### 6.6.1 法律地图

| 法律/规范 | 与爬虫相关的要点 |
|---|---|
| 《网络安全法》（2017 年施行） | 网络运营者收集使用个人信息须合法、正当、必要；不得窃取或以其他非法方式获取个人信息 |
| 《数据安全法》（2021 年施行） | 数据采集须合法正当；重要数据目录与管理义务；向境外提供数据的规则 |
| 《个人信息保护法》（PIPL，2021 年施行） | 处理个人信息须有合法性基础（同意/合同必需等）；**最小必要原则**；敏感个人信息（生物识别、行踪、金融账户等）处理门槛极高 |
| 《民法典》 | 第 1034 条起保护个人信息；第 127 条保护数据与网络虚拟财产 |
| 《刑法》 | 第 285 条：非法侵入计算机信息系统罪；**非法获取计算机信息系统数据、非法控制计算机信息系统罪**（「避开或突破安全保护措施，获取该计算机信息系统中存储、处理或者传输的数据」）；第 253 条之一：**侵犯公民个人信息罪**（非法获取/出售公民个人信息，情节严重可判刑）；第 286 条：破坏计算机信息系统罪（如高频请求拖垮目标系统） |
| 《反不正当竞争法》 | 用技术手段抓取并利用他人数据「替代」对方服务、损害其竞争优势，构成不正当竞争（互联网条款随 2025 年修订进一步细化，以现行文本为准） |
| 《著作权法》 | 网页文字、图片、数据汇编都可能受保护；整站复制、去除权利管理信息、实质性替代原作品市场均属高风险 |
| robots 协议相关自律规范 | robots.txt 虽是技术文件，但「违反 robots 协议大规模抓取」在司法实践中多次被作为认定过错/不正当竞争的因素 |

用法提示：本表是「知道去查哪部法」的地图，不是法条本身。查原文认准官方渠道（中国人大网 npc.gov.cn 的法律数据库、国家法律法规数据库 flk.npc.gov.cn），检索时注意**找现行有效版本**（法律会修订，如反不正当竞争法 2025 年修订）；司法解释与指导案例另见最高人民法院官网。网络上转贴的法条常有版本滞后，引用前务必核对。

还要说明两个边界：其一，本表只覆盖数据维度，**采集行为若伴随破解账号、干扰系统，还可能触发其他罪名**（如非法侵入计算机信息系统罪，对象是特定重要系统）；其二，平台规则（服务条款、开发者协议）虽不是法律，但违反它们是民事违约与不正当竞争认定中的关键事实，6.7 清单第 2 条「读服务条款」的分量就在这里。

### 6.6.2 高风险行为清单（务必对照）

1. 绕过登录、付费墙、验证码、接口签名等**访问控制**获取数据——刑法 285 条风险；
2. 采集**个人信息**（姓名、手机号、身份证、住址、行踪、简历、社交关系）——刑法 253 条之一与 PIPL 风险，最高发的入罪形态；
3. 把抓来的数据**用于替代原站服务**或对外提供/转售——反不正当竞争风险；
4. 高频请求影响目标系统正常运行——刑法 286 条风险（「破坏」不以有恶意为前提）；
5. 违反 robots 协议、无视站点明示拒绝继续抓取；
6. 采集内容**整站复制、去版权信息**后传播——著作权侵权；
7. 采集需权限才能访问的内部系统（含你雇主有权访问但你超出目的使用的系统）；
8. 把数据搬到境外或提供给境外主体而不做数据出境合规评估。

其中第 2 条单独展开——「个人信息」的判断比多数人以为的宽：

- 明面上的是**直接标识符**：姓名、手机号、身份证号、住址、邮箱；
- 容易被忽略的是**可识别组合**：单看无害的字段组合起来能锁定到人（如「小区名 + 车牌 + 车型」），同样按个人信息对待；
- 更敏感的是**敏感个人信息**（PIPL 定义）：生物识别、宗教信仰、特定身份、医疗健康、金融账户、行踪轨迹，以及**不满十四周岁未成年人的个人信息**——抓取即违法风险，不存在「先抓了再说」；
- 常见误判：把「网页上公开的个人主页」当成非个人信息。**公开≠豁免**，PIPL 管的是处理行为，不管信息是否已公开（已公开信息的处理也有独立规则与限制）。

### 6.6.3 公开案例讨论

以下案例信息来自公开报道与公开裁判文书，细节以判决书原文为准，此处仅作教学讨论：

- **新浪微博诉脉脉案**（北京知识产权法院，2016 年二审）：第三方应用超范围抓取并使用微博平台及用户数据。判决确立了数据获取的「三重授权原则」（用户授权平台、平台授权第三方、用户再授权第三方），明确未经授权抓取用户数据构成不正当竞争。**教训**：拿到了 API 不等于拿到了数据的全部使用权，用户数据的使用边界是独立的合规问题。
- **大众点评诉百度案**（上海浦东法院一审、上海知产法院二审，2016-2017 年）：百度地图大量抓取并展示大众点评用户评论。法院认定该使用实质替代了来源站服务，构成不正当竞争（公开报道的赔偿额数百万元级）。**教训**：数据「是公开的」不等于「可以拿来喂自己的产品」；**公开可访问 ≠ 无主数据**。
- **淘宝诉美景案**（杭州铁路运输法院，2018 年）：被告倒卖淘宝「生意参谋」数据产品的衍生数据。法院认定数据产品具有竞争性财产权益，构成不正当竞争。**教训**：对原始数据深加工形成的数据产品同样受保护，「我只是转卖数据」不是抗辩。
- **上海晟品公司爬取视频案**（上海浦东法院，2017 年，公开报道称「爬虫入刑第一案」）：被告用爬虫突破目标站点防护抓取视频数据，单位与责任人以**非法获取计算机信息系统数据罪**被判刑（罚金+有期徒刑）。**教训**：爬虫越过访问控制抓数据不是民事纠纷，而是刑事犯罪风险。
- 域外参考 **hiQ v. LinkedIn**（美国第九巡回法院多轮交锋后 hiQ 最终败诉，公开报道）：曾被解读为「公开数据随便抓」，但后续诉讼认定其违反用户协议。**教训**：域外判例风向多变，任何「外国都没事」的推断都不可靠。

四个案例的共同模式值得记住：**被告都先有一段「技术上做得到」的日子**。技术可行性的边界永远比法律边界宽——工程师的职业判断力，就体现在明知技术上能做而评估该不该做。

### 6.6.4 责任的三种形态：民事、行政、刑事

同一行为在不同严重程度下触碰的责任层级不同，工程师至少要能对号入座：

| 层级 | 典型触发 | 典型后果 |
|---|---|---|
| 民事 | 数据使用损害站点竞争优势、著作权侵权（案例：微博诉脉脉、点评诉百度） | 停止侵害、赔偿（公开报道多为数十万至数百万元级） |
| 行政 | 违反网络安全法/数据安全法的采集与数据处理义务 | 主管机关警告、罚款、责令停业 |
| 刑事 | 绕过访问控制获取数据（刑法 285 条）、非法获取公民个人信息（253 条之一）、破坏系统（286 条） | 有期徒刑、罚金——单位与直接责任人双罚 |

顺序值得注意：**刑事风险不在「商业纠纷」那一侧，而在「访问方式」这一侧**。哪怕你抓来只做学习研究，只要获取手段绕过了访问控制（登录墙/验证码/签名）或对象是公民个人信息，刑事风险就已经存在，与「用不用、赚不赚钱」无关。

### 6.6.5 公司场景：你不是「个人学习」

在企业里写爬虫，责任链条与个人完全不同，三条提醒：

1. **工作成果的责任归属是公司与个人双重**：执行「领导让抓的」不免责，实际编码者常被列为直接责任人；
2. **需求评审时把 6.7 的清单摆出来**：合规评估是需求的一部分，不是上线前的装饰——「先把数据抓回来再说」是把风险后置给写代码的人；
3. **离职交接也含数据**：带走的爬虫代码与数据副本可能同时构成侵犯商业秘密与个人信息问题。

一句话版本：**公司里写爬虫，你的专业价值恰恰在于能对不合理的需求说「这条线不能碰，有两个替代方案」**。

## 6.7 企业爬虫合规自查清单（10 条）

把清单放进代码评审流程，任何一条不过就该停下：

1. [ ] **采集目的与范围已书面化**：明确采什么字段、为什么需要、最小必要评估已做（PIPL）；
2. [ ] **robots.txt 已读取并遵守**，站点服务条款没有禁止性约定（有疑问先问法务）；
3. [ ] **身份诚实**：UA 标明项目身份与联系方式，不伪装成浏览器/他人产品；
4. [ ] **频率礼貌**：请求间隔 ≥ 0.3s、并发有上限、启用退避、错峰采集，实测不触发 429；
5. [ ] **只采公开数据**：不绕过登录/付费墙/验证码/签名，不采集需权限访问的内容；
6. [ ] **不含个人信息**：字段清单里没有姓名/手机号/身份证/行踪等（如有：停下，走 PIPL 合法性基础评估，通常结论是不采）；
7. [ ] **版权边界**：不整站复制、保留来源与作者信息、不用于替代原站服务；
8. [ ] **存储安全**：数据加密存储、访问受控、留存有期限、过期可删除（呼应数据安全法）；
9. [ ] **日志与可追溯**：采集时间、目标、量级有记录，出问题能定位到具体任务；
10. [ ] **下架与响应机制**：目标站点或数据主体提出异议时，能在约定时限内停止并删除。

## 6.8 合法替代：先找门，再翻墙吗？不——先找门

多数「爬虫需求」其实有正门，按优先级依次检查：

1. **官方 API**：目标平台多数有开放 API（含明确的使用条款与配额）——合规、稳定、不担心改版，配额就是让你按规矩用的。看文档时重点三件事：鉴权方式、速率限制、数据的使用许可范围；
2. **官方数据集/开放数据**：政府开放数据平台、Kaggle、Hugging Face Datasets、学术论文数据集——研究与学习场景九成需求已被覆盖。下载前看一眼数据许可证（License），「能在公开下载到」与「能商用」是两回事；
3. **RSS/Atom 订阅**：新闻与博客类站点提供的结构化更新通道，天生为机器消费设计，用标准库 `xml.etree` 就能解析——它是「站点主动邀请你订阅」的合法通道，不存在反爬问题；
4. **直接联系数据方**：商务合作、数据授权协议，企业级需求的正解。邮件说明用途、范围、频率，很多站点愿意给出批量导出——比对抗省下的时间远超谈判成本；
5. **本教程的两个练习站**：toscrape 系列本来就是为教学而生，学技术用它，别用真实站点练手。

一个实用的自问顺序：**「这个数据有没有官方出口？」→「有没有别人整理好的合法数据集？」→「能不能联系数据方？」**——三个问题都得到否定答案，再进入爬虫方案，并把 6.7 的清单过一遍。反过来先写爬虫再想合规，顺序本身就容易把人带进误区。

## 6.9 对照代码：合规在已有 lab 里的样子

本章偏判断与边界；作为收束，把 6.7 清单里「能在代码里找到证据」的几条映射回前几章的实际产出，你会看到合规不是口号而是几行常量：

| 清单项 | 证据位置（本仓库） |
|---|---|
| 3. 身份诚实 | `02_requests_quotes.py` 的 `HEADERS`：`crawler-lab-edu/1.0 (Python tutorial; educational use only)` |
| 4. 频率礼貌 | `02_requests_quotes.py` 的 `DELAY_SECONDS = 0.5`；`book_scrapy/settings.py` 的 `DOWNLOAD_DELAY = 0.3` + AutoThrottle；`08_async_httpx.py` 的 `Semaphore(5)` + 0.3s |
| 2. robots 已遵守 | `01_fetch_robots.py` 的标准读法；`book_scrapy/settings.py` 的 `ROBOTSTXT_OBEY = True` |
| 5. 只采公开数据 | 全部目标 URL 都是公开列表页/详情页；`07_selenium_demo.py` 的登录仅用练习站的公开测试表单 |
| 1. 采集范围书面化 | 各脚本 docstring 首段「目标站点/采集内容/产出」三要素 |
| 9. 日志可追溯 | 第 8 章 8.6 的 logging 模板；Scrapy 运行日志自带全量请求统计 |

把这张表用进你的下一个项目：新爬虫立项时照着填一遍，哪些行还空着，就是离合规还差的工作。

| 误区 | 真相 |
|---|---|
| 「robots.txt 是 404，所以可以随便抓」 | 404 只意味着「未声明限制」，频率礼貌与身份标识的义务仍在（第 1 章 1.6.2） |
| 「数据是公开的，公开=无主」 | 公开可访问只解决「能不能看到」，不解决「能不能拿来用」；大众点评诉百度案的核心正在于此 |
| 「只是学习用途，不商用就没事」 | 刑法 285/253 条之一的认定不以营利为唯一要件；「学习」也不是免责事由，规模与危害才是重点 |
| 「加个随机延迟就查不出来」 | 行为分析看的是整体模式；而且合规问题的解药从来是「不该抓就别抓」 |
| 「打码平台很成熟，说明行业默认允许」 | 工具的存在不等于使用的合法；判决书里「购买打码服务」反而是主观故意的证据 |
| 「用境外服务器抓境内数据就没事」 | 数据出境本身有专门合规要求（数据安全法），且属地管辖不以服务器位置为准 |
| 「API 配额太小，直接抓网页更快」 | 绕开官方 API 的行为模式常被认定为「恶意规避技术措施」，是加重而非减轻情节 |
| 「我抓的是数据不是代码，不涉及著作权」 | 数据汇编本身可能受保护（案例：淘宝数据产品案）；去版权信息复制更直接构成侵权 |
| 「验证码只是弹一次，手动过掉就行」 | 程序触发验证码说明访问模式已被识别，正确反应是停下评估；把「人工过码」做进流程是典型的自欺 |
| 「目标站技术上拦不住我，说明它默许」 | 防御薄弱不等于授权；司法认定看意愿表达（robots/条款/告示），不看防御强度 |
