## 6.2.1 response_model：响应过滤即安全防线

**本 lab 的真实事故（已修复并保留反面演示端点）**：最初的 `/users` 列表端点漏挂 `response_model`，实测响应里直接泄漏了 `password` 字段；挂上 `response_model=list[UserOut]` 后字段被自动过滤。lab 里保留了一个 `/leaky-users` 反面端点供对比：

```text
$ curl -s "http://127.0.0.1:8101/users?limit=1"
[{"id":1,"name":"alice","role":"admin","email":"alice@example.com"}]     # ✅ 无 password

$ curl -s "http://127.0.0.1:8101/leaky-users?limit=1"
{...,"items":[{"id":1,...,"password":"never-return-this",...}]}          # ⚠️ 泄漏！
```

```python
class UserOut(BaseModel):
    id: int
    name: str
    role: str
    email: str            # 注意：没有 password 字段

@app.get("/users/{user_id}", response_model=UserOut)
def get_user(user_id: int) -> dict:
    return USERS[user_id]     # 返回值多出的字段会被 Pydantic 自动剔除
```

三条军规：

1. 每个返回模型的端点**必须**挂 response_model
2. 内部对象（含密码/密钥）与对外契约**必须**分开定义
3. code review 时把「漏挂 response_model」当 bug 级问题看待

## 6.2.2 依赖注入 Depends：三种形态

### 形态一：函数依赖（可复用参数组）

```python
def pagination(limit: int = Query(10, ge=1, le=100), offset: int = Query(0, ge=0)):
    return {"limit": limit, "offset": offset}

@app.get("/users")
def list_users(page: dict = Depends(pagination)): ...
```

分页参数写一次，所有列表端点复用；校验规则自动进 /docs。

### 形态二：yield 依赖（资源管理）

```python
def get_conn():
    conn = connect()
    try:
        yield conn          # 响应前把连接交给路由
    finally:
        conn.close()        # 无论成败，请求结束必关闭
```

这是数据库连接的标准姿势（03 章全面使用）。

### 形态三：依赖嵌套

```python
def current_user(token: str = Depends(oauth2_scheme)): ...      # 依赖 oauth2_scheme
def admin_only(user: dict = Depends(current_user)): ...         # 再依赖 current_user
```

依赖可以叠依赖，认证体系（04 章）就是这么搭起来的。

**实测记录**（lab 02）：

```text
$ curl -s http://127.0.0.1:8101/stats
{"users":2,"admins":1}

$ curl -s "http://127.0.0.1:8101/users?limit=1&offset=1"
[{"id":2,"name":"bob","role":"user","email":"bob@example.com"}]
```

## 6.2.3 中间件：请求计时器

```python
@app.middleware("http")
async def add_timing(request, call_next):
    start = time.perf_counter()
    response = await call_next(request)
    cost_ms = (time.perf_counter() - start) * 1000
    response.headers["X-Process-Time"] = f"{cost_ms:.1f}ms"
    if cost_ms > 50:
        logger.warning("慢请求 %s 耗时 %.1fms", request.url.path, cost_ms)
    return response
```

实测响应头：

```text
$ curl -sI http://127.0.0.1:8101/stats | grep -i x-process-time
x-process-time: 0.2ms
```

## 6.2.4 后台任务 BackgroundTasks

```python
@app.post("/mail")
def send_mail(to: str, tasks: BackgroundTasks) -> dict:
    tasks.add_task(send_welcome_email, to)   # 先响应，后执行
    return {"queued": True, "to": to}
```

实测：响应立即返回 `{"queued":true}`，1.5 秒后日志出现「欢迎邮件已发送」。适用轻量异步（发邮件/写日志）；重任务上任务队列（Celery/ARQ）。

## 6.2.5 Pydantic v2 进阶速览

| 能力 | 写法 | 场景 |
|---|---|---|
| 自定义校验 | `@field_validator("title")` | 标题去空白等业务规则 |
| 模型配置 | `model_config = ConfigDict(from_attributes=True)` | 接受 ORM 对象构造 |
| 派生字段 | `@computed_field` | 序列化时自动计算 |
| 嵌套模型 | 字段类型是另一个 BaseModel | 复杂响应结构 |

## 常见坑与排查

| 现象 | 原因 | 解决 |
|---|---|---|
| 响应多了内部字段 | 漏挂 response_model | 军规 1（本 lab 真实事故） |
| Depends 的参数校验不生效 | 校验参数在依赖函数里写错位置 | 用 Query()/Path() 显式声明 |
| yield 依赖的资源没释放 | finally 缺失 | 模板见 6.2.2 |
| 中间件里改响应体无效 | StreamingResponse 时机 | 改 headers 安全，body 用响应类处理 |
| BackgroundTasks 任务丢失 | 进程重启 | 关键任务上任务队列 |
